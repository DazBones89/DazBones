# ①② 実装・運用メモ（2026-09-14）

## 実装内容

- 画像は5MBを上限に、拡張子・MIME・デコード可能な実体を検証。JPEG/PNG/WebPに対応し、集合写真はJPEG。25メガピクセルを上限とし、不正画像や保存失敗時には旧画像を保持。
- 選手成績の入力名を「打数」に統一。選手・道具・年会費の値を検証。道具の作成日時を更新時に保持し、既存の削除済み所有者も保持可能。
- 祝日CSVは全行を検証してから一括登録。不正行・ファイル内重複がある場合は全件を登録しない。UTF-8 BOMと見出し行に対応。
- 回答者の削除・復元・本人コード発行を管理者に限定。メンバーは本人分のみ回答でき、共有編集者コードはアンケート閲覧のみ。代理回答と手動アンケート作成・削除は管理者のみ。
- 回答送信中の二重送信を抑止し、通信エラーを画面内に表示。土日祝に重なる手動アンケートを削除しても、自動アンケートと回答は保持。
- 年会費を年度・選手単位で保存。年度合計、チーム全期間累計、個人の年度履歴と累計を表示。請求・入金・未入金額に対応し、競合更新を拒否。
- お知らせを一般公開／ログインメンバー限定に分割。記事URLへの直接アクセスでも公開範囲を検証。
- 管理者コード変更をDBに保存し、全権限の既存セッションを次のリクエストで失効させる。変更した管理者本人もログアウト。再起動後も変更を保持。
- 活動履歴を年度別に表示。代替画像や入力結果のメッセージも整理。

## 今回具体化した初期設定

年度は1月〜12月。既存部費は2026年度として移行し、支払済フラグのある額を入金額とする。既存のお知らせ3件は一般公開として維持。累計は請求・入金・未入金の3種類。年度開始月などを変更する場合は、集計と既存データの割当をあわせて変更する。

本人確認には、管理者が「回答者管理」で発行するメンバー専用ID・コードを使用する。コードは発行直後に一度だけ表示される。再発行は旧コードを無効化する。回答者を削除すると旧コード・セッションを失効させ、復元後も新たなコード発行が必要。

## DB移行

既存スキーマを前提とするFlyway V1を追加。旧 `fee` は削除せず、`annual_fees` にコピーする。認証テーブルと記事の公開区分も追加する。

別環境では、DB全体をバックアップした後、一度だけ次のコマンドで起動する。Flywayは適用済み移行を再実行しない。

```powershell
.\gradlew.bat bootRun --args="--spring.flyway.enabled=true"
```

ローカルMySQLには適用済み。バックアップはGit管理対象外の `backups/before-phase2-20260914.sql`。移行後は年会費9件、請求15,000円、入金10,000円で移行前と一致し、旧部費9件も保持している。通常は `./gradlew.bat bootRun` で起動できる。
