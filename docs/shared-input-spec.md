# 現行仕様：共通ログインと一括入力（2026-09-18）

## 権限

一般公開（未ログイン）、選手、masterの3区分。選手は共通コードでログインし、本人確認・本人との名簿紐付けは使わない。選手はmaster専用機能以外を管理できる。

master専用は、選手項目の表示設定、選手ごとの表示チェック、祝日管理、ログインコード変更、操作履歴。権限をサーバーでも検証する。コード変更は全セッションを失効させる。旧admin/editor/member-IDの認証は受け付けない。

コードそのものはGitへ保存しない。ローカルの指定コードはignoredの `config/local.properties` の `app.auth.master-code` / `app.auth.player-code` で初期設定する。登録後はDBのハッシュが優先され、再起動しても変更を保持する。Dockerでは従来の環境変数 `ADMIN_CODE` がmaster、`EDITOR_CODE` が選手の初期コードに対応する。既存DBを移す場合も、新区分の初回起動前に値を設定する。

## 機能別の入力画面（2026-09-19更新）

メニューには「一括入力」を設けない。各入力画面には打撃成績・部費・道具管理・出欠確認の共通タブを表示し、画面内で切り替えられる。打撃成績 `/players/stats`、部費 `/fee`、道具管理 `/gear`、出欠確認 `/survey/attendance` を各メニューから直接開く。内部の保存処理は共用し、自動保存を維持する。旧 `/input` は対応する機能別画面へ転送する。

- 打撃成績は選択した選手の打数と安打だけ。打率を計算し表示する。
- 部費は1月〜12月の年度単位。支払い済みチェック、金額（円、0〜100000000の整数）、1000文字以内のコメント。左側に未払いの名前、右側に支払い済みの名前と金額を一覧表示し、未登録の在籍選手は未払いとする。月別・支払日の入力は設けない。年度を切り替えて履歴を確認する。
- 道具は種類名・名簿から選ぶ持ち主・コメント。選手も追加・削除可能。
- 出欠確認は対象月、名前、○△×、500文字以内のコメント。共通コード利用者は誰の回答でも変更できる。

選択値は即時、文字・数値は入力停止後または欄を離れた時に自動保存する。保存中／保存済み／失敗を表示し、失敗時は入力を保持して再試行できる。画面内の切り替えは保存終了を待ち、未保存のままページを離れる場合はブラウザに確認を求める。他利用者からのリアルタイム配信はしない。バージョン検証で古いデータの上書きを拒否する。

## 出欠確認

各年の1〜12月をプルダウンで選択。土日と祝日管理に登録された日を自動表示し、選手・masterは編集欄から日付を追加できる。重複を除いて昇順にする。祝日の外部自動取得はない。

日ごとに○△×の人数を表示し、日付を選ぶと回答済みの人の名前・結果・コメントだけを表示する。未回答者の行は表示しない。未回答は×とは区別する。前後の日付へ移動可能。1選手・1日につき1回答。

その他アンケートと回答者管理の旧画面・APIを廃止。旧URL `/survey` / `/survey/attendance` は新画面へ案内する。旧データは削除せずDBに保持する。

## 選手紹介

プロフィール編集は別画面。masterが項目を非表示にすると他の役割の一覧・登録・編集・一括入力でも非表示にし、更新要求でも既存値を保持／拒否する。名前非表示時は選択用の代替ラベル「選手 #ID」を使う。打数または安打が非表示なら逆算防止のため打率も他の役割へ返さない。

masterが選手ごとのチェックを外すと論理削除となる。通常の名簿から除外し、成績・部費・過去回答を保持。masterは一覧から復元できる。

## お知らせ

一覧・ホームとも一本化。未ログインでは公開記事のみ、ログイン後は選手用も表示。選手用タイトルに【選手用】を一度だけ付け、公開日時・直接URLでの閲覧制限を維持する。

## データ移行

Flyway V4で選手・道具のversion、部費のpaid、表示設定と手動対象日を追加する。旧請求額・入金額は保持し、既存の請求額が正で全額入金済みの行を支払い済みに移行する。自由記述金額からの累計は行わず、旧金額累計は新画面へ表示しない。既存の○△回答は維持する。
