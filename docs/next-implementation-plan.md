# 次の実装候補（2026-09-14）

①②の実装後に残る作業を整理した当初の提案。2026-09-17時点で1〜3を実装した。実装範囲・検証結果・公開先決定後に残る作業は `phase3-implementation.md` を参照。4は引き続き追加機能の候補。

## 1. 画面の仕上げ

- PCでも見やすい幅・配置に対応（現状は共通レイアウト最大480px）。スマホの固定ナビと長文・入力画面の重なりも確認する。
- 下部ナビの現在地表示、メニューの開閉状態、モーダルのEscape操作とフォーカス移動・復帰、入力ラベルを整える。
- トップの同じ集合写真4枚の仮表示を整理する。写真ページは現在集合写真1枚のため、複数写真の登録・一覧を採用するか決める。
- 権限ごとのログイン→登録→編集→ログアウトを実ブラウザで確認する。現在の39件はサーバー側中心のテストで、スマホ実機の操作保証ではない。

## 2. 公開できる環境の整備

- 空のDBから構築する初期スキーマを追加し、現在のFlyway差分移行とあわせて別環境で再現する。
- 本番設定、永続画像保存先、HTTPS、起動・更新・障害調査手順を用意する。公開先は選定が必要。
- DBと画像のバックアップ・復元手順を実装し、復元テストを行う。保存頻度と保持世代を決める。
- テスト・ビルドをGitHub Actionsで自動化する。Tailwindの実行時CDN依存をビルド済みCSSに切り替え、外部資産も固定管理する。
- 過去のGit履歴に残る認証情報を本番では交換する。既存DBの管理者コードはDB保存値が優先されるため、設定ファイル変更だけでは交換されない。

## 3. 複数人で使う際の安定性

- アンケートを日付範囲でまとめて取得し、日ごとの繰り返し問い合わせを減らす。
- 年会費以外の予定・回答・祝日などにも、同時作成・同時更新時の整合性とエラー復帰を確認・実装する。
- 更新者・更新日時・対象・操作内容の履歴を追加する。共有管理者／編集者コードでは個人までは特定できないため、記録粒度または個別アカウント化を決める。

## 4. 採用する場合の追加機能

- LINE通知と通知設定・送信履歴・失敗時の再送。通知対象とタイミングの確定、外部サービス設定が必要。
- Instagram連携または写真アルバム。掲載先アカウントと公開範囲の確定が必要。
- アンケート締切、予定との連携、同日に複数の活動を扱う機能。
- 入金1回ごとの明細・履歴。現在は年度ごとの入金合計を保持しており、入金イベントごとの台帳は別機能。
- アクセス解析、ダークモード・表示設定、問い合わせ先・規約の掲載内容。

おすすめの着手順は「画面の仕上げ → 公開環境・復元・CI → 同時利用対策」。外部連携は必要なものを選んで追加する。
